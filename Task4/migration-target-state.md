# Образ целевого результата -  что именно должно измениться за 12 месяцев

## Какие системы остаются 
- MDM-единый источник истины по клиентам и справочникам;
- Kafka-событийная шина; 
- DWH - витрины для BI; 
- Data Lakehouse (S3/MinIO + Delta/Iceberg)-сырые и исторические данные; 
- Airflow + dbt-оркестрация и трансформации; 
- DataHub-каталог, lineage, владельцы; 
- BI;
- Target Core Banking - как мастер‑системы по счетам/транзакциям и договорам, образовалась из FU Core; 
- Target Card Platform (из FU Cards);
- Target Lending Platform (из FU Loans);
- Payment Hub; 
- Target Case Platform (обращения клиентов);
- Integration Layer.

## Какие выводятся из эксплуатации
- RB CRM (замена: MDM + Target Core)
- RB Core (замена: Target Core)
- RB Cards (замена: Target Card Platform)
- RB Loans (портфель — в Target Lending Platform);
- RB DWH (заменён единым DWH);
- RB BI (заменён единым BI);
- старые выгрузки в Excel/CSV «вручную» (ручные отчёты, самописные скрипты);
- локальные витрины в файлах и неподдерживаемых базах (Access, старые MySQL‑песочницы команд);
- прямые запросы из Core в BI (обход DWH);
- point-to-point интеграции RetailBank;
- коннекторы без mTLS (небезопасные интеграции).

## Какие данные мигрируются
- клиентские профили из разрозненных CRM в MDM (с дедупликацией и маппингом на global_client_id); 
- истории транзакций из архивов Core в Lakehouse (в неизменяемом виде); 
- справочники статусов и продуктов в единые витрины DWH; 
- остатки и текущие статусы счетов в витрины DWH для BI и UI (Naive UI).

## Какие потоки переключаются
- потоки транзакций: с прямых выгрузок/ручных файлов -> на CDC (Debezium) -> Kafka -> DWH/Lakehouse; 
- клиентские данные: с разрозненных источников -> в MDM -> далее во все системы по global_client_id; 
- отчётные выгрузки: с ручных скриптов -> на пайплайны Airflow -> подписанные/зашифрованные файлы для регулятора; 
- отчётность по обращениям переключается с двух Case-систем на единую Case Platform → поисковый движок |
- события каналов (чат, мобильное приложение): в Kafka -> Lakehouse -> агрегаты в DWH.
- point-to-point потоки RB заменяются на публикацию в Kafka и CDC-коннекторы; 

## Критерии завершения перехода
- 100% транзакций загружаются через CDC/Kafka (без ручных файлов); 
- 100% клиентов имеют единый golden client_id в MDM без открытых конфликтов матчинга; 
- все системы используют global_client_id из MDM; 
- все потоки данных работают через Integration Layer/Kafka/CDC, ни одной point-to-point интеграции не осталось; 
- SLA витрин BI ≤ 1 ч, статусов ≤ 15 мин; 
- наличие lineage в DataHub для всех ключевых витрин; mTLS включён на всех интеграционных потоках; 
- проведены тесты фолбэка (переключение на резерв, восстановление из бэкапа); 
- документация по data‑продуктам (владелец, SLA, контракт) зафиксирована в DataHub; 
- DWH и Data Lakehouse — единственные источники для BI и регуляторной отчётности.
