# Правила владения данными

## Физ. лицо

| Роль | Значение |
|---|---|
| Data Owner | Розничный бизнес совместно с МСБ (по типу Физ. лица) |
| Data Steward | Data Office |
| Producer | FU CRM, RB CRM (фронт-офис при онбординге) |
| Consumer | Core Banking, Cards, Loans, Контактный центр, BI, Риск-менеджмент |
| Правила изменения | Операции с персональными данными физических лиц выполняются исключительно в рамках CRM/MDM workflow с обязательным подтверждением; прямой доступ к редактированию в DWH/Lakehouse не предоставляется |
| Правила качества | При регистрации клиента обязательна проверка ИНН/СНИЛС/иных реквизитов через внешние реестры (ФНС/ПФР); перед формированием золотой записи запускается процесс дедупликации; контролируется заполнение всех требуемых полей |

## Счёт

| Роль | Значение |
|---|---|
| Data Owner | Розничный бизнес / МСБ (владелец продукта) |
| Data Steward | ИТ (команда Core Banking) |
| Producer | FU Core, RB Core |
| Consumer | Карты, Кредиты, DWH, BI, Финансовый департамент |
| Правила изменения | Все операции с данными счетов осуществляются исключительно через Core Banking; корректировки баланса производятся только стандартными проводками, прямое обновление записей запрещено |
| Правила качества | Еженедневная сверка остатков с итогами проводок; автоматический контроль уникальности номеров счетов/IBAN |

## Карта

| Роль | Значение |
|---|---|
| Data Owner | Карты — бизнес (в составе Розничного бизнеса) |
| Data Steward | ИТ (команда карточного процессинга) |
| Producer | FU Cards, RB Cards |
| Consumer | DWH, BI, антифрод-система, контактный центр |
| Правила изменения | Любые изменения данных карты проходят через карточный процессинг; смена статуса возможна только по регламентированным событиям — выпуск, блокировка, перевыпуск |
| Правила качества | Строгое соответствие требованиям PCI DSS (запрет на хранение полного PAN/CVV за пределами процессинга); проверка привязки карты к активному счёту |

## Кредит

| Роль | Значение |
|---|---|
| Data Owner | Риск-менеджмент |
| Data Steward | ИТ (команда кредитной системы) |
| Producer | FU Loans, RB Loans |
| Consumer | Финансовый департамент (резервы, отчётность), DWH, BI |
| Правила изменения | Смена статуса и графика платежей выполняется исключительно кредитной системой на основании регламентированных событий — просрочка, реструктуризация |
| Правила качества | Единая методология расчёта просрочки и определения дефолта (маппинг различий между FU/RB в переходный период); сверка суммы выдачи с утверждённым графиком платежей |

## Договор

| Роль | Значение |
|---|---|
| Data Owner | Юридический блок совместно с продуктовым бизнес-подразделением |
| Data Steward | Data Office |
| Producer | CRM/Core в момент подписания |
| Consumer | Счёт, Кредит, Карта (как основание), аудит, комплаенс |
| Правила изменения | Корректировка статуса договора допускается только в рамках утверждённого процесса (расторжение, пролонгация); текстовое содержимое подписанного документа изменению не подлежит |
| Правила качества | Обязательное прикрепление скан-копии или электронной подписи; гарантия уникальности номера договора |

## Транзакция

| Роль | Значение |
|---|---|
| Data Owner | Финансовый департамент совместно с Core Banking |
| Data Steward | ИТ |
| Producer | FU Core, RB Core, FU Cards, RB Cards |
| Consumer | DWH, Data Lakehouse, антифрод, BI, регулятор (через отчётность) |
| Правила изменения | Зарегистрированная транзакция не подлежит изменению (принцип append-only); любые корректировки вносятся исключительно новыми компенсирующими записями |
| Правила качества | Автоматическая проверка баланса дебет/кредит; предотвращение создания дубликатов при параллельной работе систем FU/RB на переходный период |

## Платёж

| Роль | Значение |
|---|---|
| Data Owner | Финансовый департамент совместно с Комплаенс/AML |
| Data Steward | ИТ + Комплаенс |
| Producer | Core Banking, платёжные шлюзы |
| Consumer | AML-мониторинг, DWH, регулятор |
| Правила изменения | Статус платежа обновляется только платёжной системой по итогам обработки; ручной ввод изменений не допускается |
| Правила качества | Предварительный AML/санкционный скрининг обязателен до перевода платежа в статус «исполнен»; контроль полноты реквизитов получателя |

## Продукт

| Роль | Значение |
|---|---|
| Data Owner | Product Management (Розница/МСБ) |
| Data Steward | Data Office |
| Producer | Product Management через CRM/Core (конфигурация) |
| Consumer | Все продуктовые системы (Core, Cards, Loans), CRM, BI |
| Правила изменения | Корректировка параметров продукта выполняется через процедуру согласования product-команды с обязательным версионированием |
| Правила качества | Гарантия уникальности кода продукта; валидация актуальности условий перед публикацией конфигурации в MDM |

## Обращение Физ. лица

| Роль | Значение |
|---|---|
| Data Owner | Контактный центр |
| Data Steward | Data Office |
| Producer | CRM/Case-система при регистрации обращения |
| Consumer | BI, Product Management (анализ жалоб), Риск-менеджмент (жалобы по мошенничеству) |
| Правила изменения | Изменение статуса обращения допускается только оператором или системой Case-менеджмента в рамках установленного SLA |
| Правила качества | Обязательная привязка к client_id (после матчинга в MDM); контроль соблюдения сроков ответа по SLA |

## Отделение

| Роль | Значение |
|---|---|
| Data Owner | Розничная сеть / административный блок |
| Data Steward | Data Office |
| Producer | CRM (регистрация точки обслуживания) |
| Consumer | Договор (место заключения), региональная отчётность |
| Правила изменения | Создание и закрытие отделений выполняется исключительно через административный процесс |
| Правила качества | Единый справочник регионов и адресов; исключение дублирования кодов отделений |

## Тариф

| Роль | Значение |
|---|---|
| Data Owner | Product Management |
| Data Steward | Data Office |
| Producer | Product Management через CRM/Core |
| Consumer | Карта, Счёт, Кредит |
| Правила изменения | Изменение тарифного плана осуществляется через согласованную процедуру с указанием периода действия; запись в историю не перезаписывается |
| Правила качества | Исключение пересечений периодов действия тарифов на один продукт; обязательная привязка к product_id |

## Юр. лицо

| Роль | Значение |
|---|---|
| Data Owner | Риск-менеджмент / Комплаенс |
| Data Steward | Data Office |
| Producer | Core Banking (при регистрации операции с новым Юр. лицом) |
| Consumer | Антифрод (графовая БД), Платёж, Кредит (поручители) |
| Правила изменения | Корректировка реквизитов возможна только после верификации через внешние источники (БИК-справочник ЦБ, ЕГРЮЛ) |
| Правила качества | Обязательная проверка по санкционным/стоп-листам; контроль соответствия формата ИНН/БИК |
